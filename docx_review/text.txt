P12: 流水线原理
P13: 五级流水线主要包括：取指（IF）、译码（ID）、执行（EX）、访存（MEM）和写回（WB）这五个阶段。每个阶段负责干一件事情：
P14: IF:取出pc当前指向的指令
P15: ID:把 IF 阶段取出来的指令进行解析，确定这条指令要做什么，并读取需要的寄存器数据。
P16: EX:根据 ID 阶段解析出来的信息，真正执行指令需要的计算操作。
P17: MEM:访问数据存储器，完成加载或存储操作。
P18: WB:把计算结果或者从内存读取的数据，写回寄存器堆
P19: 但是里面会有一些地方需要注意。具体来说，五级流水线可能会出现数据冒险的问题。这个问题可以通过数据前推和阻塞气泡来解决。为了解决这个问题，我在每个阶段之间插入一个中间阶段来保存上一阶段的临时数据。
P20: 实现细节以及代码讲解
P21: 整体结构

P23: 采用经典的五级流水线 MIPS 处理器结构，流水线阶段依次为：
P24: IF → ID → EX → MEM → WB
P25: 各阶段之间使用流水线寄存器传递数据和控制信号：
P26: IF/ID → ID/EX → EX/MEM

P29: 2 五级流水线 CPU 实现细节与相关代码
P30: 本设计采用 IF、ID、EX、MEM、WB 五级流水线结构，各阶段之间通过流水线寄存器传递数据和控制信号。顶层模块 mips_pipeline_top 主要负责连接各个子模块，具体运算由各流水线阶段完成。

P33: assign next_pc =
P34: id_jump
P35: ? (is_jump_register ? id_rs_value : jump_addr)
P36: : (branch_taken ? branch_addr : pc_next4);

P57: if (!clrn) begin
P58: pc <= 32'h00000000;
P59: end
P60: else begin
P61: pc <= pc_next;
P62: end
P63: end
P64: always @(*) begin
P65: pc_next = pc;
P66: if (wpc) begin
P67: pc_next = npc;
P68: end
P69: end

P116: assign rt = if_id_ins[20:16];

P118: 立即数扩展根据指令类型选择零扩展或符号扩展：
P119: always @(*) begin
P120: case (opcode)
P121: 6'b001100,
P122: 6'b001101,
P123: 6'b001110,
P124: 6'b001111: begin

P126: 16'h0000,
P127: immediate16
P128: };
P129: end
P130: default: begin

P139: assign branch_target =if_id_pc4 + {extended_immediate[29:0], 2'b00};

P141: assign rs_data =(mem_wb_regwrite &&(mem_wb_rd != 5'd0) &&(mem_wb_rd == rs))? wb_data: rs_raw_value;

P144: 2.5 load-use 冒险检测
P145: load_use_hazard
P146: 该模块检测 ID/EX 阶段的 load 指令是否会与 ID 阶段指令产生数据相关。
P147: assign source_dependency =
P148: (id_ex_rt == id_rs) ||
P149: (id_ex_rt == id_rt);
P150: always @(*) begin
P151: stall  = 1'b0;
P152: bubble = 1'b0;
P153: if (id_ex_memread && source_dependency) begin
P154: stall  = 1'b1;
P155: bubble = 1'b1;
P156: end
P157: end
P158: 发生冒险时：
P159: PC 停止更新；
P160: IF/ID 寄存器停止更新；
P161: ID/EX 寄存器清零；
P162: 执行阶段插入一个 NOP。
P164: 2.6 ID/EX 流水线寄存器
P165: decode_execute_reg
P166: 该模块保存 ID 阶段产生的操作数、立即数、寄存器编号和控制信号。控制优先级为：
P167: if (!clrn) begin
P168: // 异步复位
P169: end
P170: else if (bubble) begin
P171: // 清空寄存器，插入 NOP
P172: end
P173: else if (stall) begin
P174: // 保持原值
P175: end
P176: else begin
P177: // 锁存 ID 阶段数据
P178: end
P179: 其中 bubble 的优先级高于 stall，保证检测到 load-use 冒险时能够正确插入气泡。
P181: 2.7 EX 执行阶段
P182: execute_stage
P183: EX 阶段主要完成 ALU 运算、操作数选择、数据前递、目的寄存器选择以及 jal 返回地址生成。
P184: ALU 操作数选择逻辑如下：
P185: always @(*) begin
P186: alu_operand_a = ex_rs_data;
P187: alu_operand_b = ex_rt_data;
P188: if (is_shift_instruction) begin
P189: alu_operand_a = {
P190: 27'h0000000,
P191: ex_imm_out[10:6]
P192: };
P193: end
P195: if (use_immediate_operand) begin
P196: alu_operand_b = ex_imm_out;
P197: end
P199: if (!is_shift_instruction) begin
P200: if (ex_mem_regwrite &&
P201: (ex_mem_rd != 5'd0) &&
P202: (ex_mem_rd == ex_rs)) begin
P203: alu_operand_a = ex_mem_alu_result;
P204: end
P205: else if (mem_wb_regwrite &&
P206: (mem_wb_rd != 5'd0) &&
P207: (mem_wb_rd == ex_rs)) begin
P208: alu_operand_a = mem_wb_wb_data;
P209: end
P210: end
P211: end
P212: 目的寄存器选择规则如下：
P213: assign ex_dst_reg =
P214: is_jump_link
P215: ? 5'd31
P216: : ((ex_aluop == 2'b10) ? ex_rd : ex_rt);
P217: 其中：
P218: R 型指令使用 rd；
P219: I 型指令使用 rt；
P220: jal 固定使用 $31。
P221: jal 的写回值为：
P222: assign link_address = ex_pc4 + 32'd4;
P223: assign alu_result = is_jump_link ? link_address : alu_raw_result;
P224: 因为 ex_pc4 已经是当前指令地址加 4，所以最终写回值为 PC + 8。

P227: execute_memory_reg
P228: 该模块负责将 EX 阶段的结果传递到 MEM 阶段。
P229: always @(posedge clk or negedge clrn) begin
P230: if (!clrn) begin
P231: exm_alu_result  <= 32'h00000000;
P232: exm_store_wdata <= 32'h00000000;
P233: exm_rd          <= 5'd0;
P234: exm_rt_num      <= 5'd0;
P235: exm_memwrite    <= 1'b0;
P236: exm_memread     <= 1'b0;
P237: exm_memtoreg    <= 1'b0;
P238: exm_regwrite    <= 1'b0;
P239: end
P240: else begin
P241: exm_alu_result  <= alu_result;
P242: exm_store_wdata <= store_rt_data;
P243: exm_rd          <= rd;
P244: exm_rt_num      <= ex_rt_num;
P246: exm_memwrite    <= memwrite;
P247: exm_memread     <= memread;
P248: exm_memtoreg    <= memtoreg;

P250: end
P251: end
P252: 该寄存器不需要 stall 或 bubble 控制，每个时钟周期都将 EX 阶段结果推进到 MEM 阶段。
P254: 2.9 MEM 访存阶段
P255: memory_stage
P256: MEM 阶段负责数据存储器的读写，并将 EX/MEM 阶段的数据传递到 MEM/WB 阶段。
P257: sw 指令的存储数据支持 MEM/WB 到 MEM 的前递：
P258: always @(*) begin
P259: store_data_final = 32'h00000000;
P260: if (exm_memwrite) begin
P261: store_data_final = exm_store_wdata;
P262: if (mem_wb_regwrite &&
P263: (mem_wb_rd != 5'd0) &&
P264: (mem_wb_rd == exm_rt_num)) begin
P265: store_data_final = mem_wb_wb_data;
P266: end
P267: end
P268: end
P269: 数据存储器写入和读取如下：
P270: always @(posedge clk) begin
P271: if (exm_memwrite) begin
P272: data_memory[data_address] <= store_data_final;
P273: end
P274: end
P275: assign mem_read_data = data_memory[data_address];
P276: 其中：
P277: 写操作在时钟上升沿进行；
P278: 读操作为组合读；
P279: data_address = exm_alu_result[7:2]。
P281: 2.10 MEM/WB 流水线寄存器
P282: memory_writeback_reg:负责将数据写回寄存器堆
P283: always @(posedge clk or negedge clrn) begin
P284: if (!clrn) begin
P285: wb_alu_result <= 32'h00000000;
P286: wb_read_data  <= 32'h00000000;
P287: wb_rd         <= 5'd0;
P288: wb_memtoreg   <= 1'b0;
P289: wb_regwrite   <= 1'b0;
P290: end
P291: else begin
P292: wb_alu_result <= mem_alu_result;
P293: wb_read_data  <= mem_read_data;
P294: wb_rd         <= mem_rd;

P296: wb_regwrite   <= mem_regwrite;
P297: end
P298: end
P299: 最终写回数据由顶层模块选择：
P300: assign write_back_value =
P301: mem_wb_to_reg
P302: ? mem_wb_read_data
P303: : mem_wb_alu_result;
P304: 当 mem_wb_to_reg = 1 时，写回数据来自数据存储器；否则来自 ALU。

P429: 3.4 数据前推机制
P430: 流水线中，前一条指令的结果可能还没有写回寄存器，但后一条指令已经进入 EX 阶段。为解决这一问题，本设计设置了多级数据前推通路。

P435: (ex_mem_rd != 5'd0) &&
P436: (ex_mem_rd == ex_rs)) begin
P437: alu_operand_a = ex_mem_alu_result;
P438: end
P439: else if (mem_wb_regwrite &&
P440: (mem_wb_rd != 5'd0) &&
P441: (mem_wb_rd == ex_rs)) begin
P442: alu_operand_a = mem_wb_wb_data;
P443: end
P444: 操作数 B 的前推只对寄存器型指令有效：
P445: if (!use_immediate_operand) begin
P446: if (ex_mem_regwrite &&
P447: (ex_mem_rd != 5'd0) &&
P448: (ex_mem_rd == ex_rt)) begin
P449: alu_operand_b = ex_mem_alu_result;
P450: end
P451: else if (mem_wb_regwrite &&
P452: (mem_wb_rd != 5'd0) &&
P453: (mem_wb_rd == ex_rt)) begin
P454: alu_operand_b = mem_wb_wb_data;
P455: end
P456: end
P457: 例如，测试程序中的：
P458: ori  r8, r5, 0xffff
P459: xori r8, r8, 0x5555
P460: 第二条指令需要立即使用第一条指令产生的 r8。此时结果可以通过 EX/MEM 前推直接送入 ALU，而不需要等待寄存器写回。
P462: 3.5 分支比较前推
P463: beq 和 bne 在 ID 阶段完成比较，因此分支比较器也需要获得最新的寄存器值。
P464: 分支操作数前推顺序为：
P465: EX → EX/MEM → MEM/WB → 寄存器堆
P466: if (ex_regwrite &&
P467: !ex_memread &&
P468: (ex_rd != 5'd0) &&
P469: (ex_rd == rs)) begin
P471: branch_rs_value = ex_alu_result;
P472: end
P473: else if (ex_mem_regwrite &&
P474: !ex_mem_memread &&
P475: (ex_mem_rd != 5'd0) &&
P476: (ex_mem_rd == rs)) begin
P478: branch_rs_value = ex_mem_alu_result;
P479: end
P480: else if (mem_wb_regwrite &&
P481: (mem_wb_rd != 5'd0) &&
P482: (mem_wb_rd == rs)) begin
P484: branch_rs_value = wb_data;
P485: end
P486: 对于 load 指令，由于其数据在 EX 阶段尚未读出，因此禁止从 EX 或 EX/MEM 阶段前推 load 数据。
P488: 3.7 Load-use 冒险处理
P489: load 指令的数据必须经过 MEM 阶段的存储器读取后才能得到，因此无法在 EX 阶段直接前推。当一条 lw 指令后面紧跟着使用该结果的指令时，会产生 load-use 冒险。
P490: 测试程序中的典型指令为：
P491: lw  r9, 0(r4)
P492: add r8, r8, r9
P493: 以及：
P494: lw  r9, 0(r4)
P495: sub r8, r9, r4
P496: 冒险检测模块比较 ID/EX 阶段 load 指令的目标寄存器和 ID 阶段指令的源寄存器：
P497: assign source_dependency =
P498: (id_ex_rt == id_rs) ||
P499: (id_ex_rt == id_rt);
P500: always @(*) begin
P501: stall  = 1'b0;
P502: bubble = 1'b0;
P503: if (id_ex_memread && source_dependency) begin
P504: stall  = 1'b1;
P505: bubble = 1'b1;
P506: end
P507: end
P508: 检测到冒险时：
P509: PC 停止更新；
P510: IF/ID 寄存器保持不变；
P511: ID/EX 寄存器清零；
P512: EX 阶段插入一个 NOP。
P513: 对应控制连接如下：
P514: .wpc(~pipeline_stall)
P515: .en(~pipeline_stall)
P516: .stall (pipeline_stall)
P517: .bubble(pipeline_bubble)
P518: ID/EX 寄存器中，bubble 优先级高于 stall：
P519: if (!clrn) begin
P520: clear_pipeline_state;
P521: end
P522: else if (bubble) begin
P523: clear_pipeline_state;
P524: end
P525: else if (stall) begin
P526: // 保持当前值
P527: end
P528: else begin
P529: capture_decode_state;
P530: end
P531: 经过一个周期的阻塞后，lw 指令进入 MEM 阶段并得到数据，后继指令再通过 MEM/WB 前推获得正确结果。
P533: 3.8 分支和跳转指令
P534: 分支目标地址由 PC + 4 加上符号扩展后的偏移量得到：
P535: assign branch_target =
P536: if_id_pc4 + {extended_immediate[29:0], 2'b00};
P537: beq 和 bne 的判断逻辑如下：
P538: assign take_branch =
P539: branch &&
P540: (
P541: is_bne
P542: ? (branch_rs_value != branch_rt_value)
P543: : (branch_rs_value == branch_rt_value)
P544: );
P545: j 和 jal 使用指令中的 26 位目标字段，并与当前 PC 的高 4 位拼接：
P546: assign jump_addr = {
P547: pc_q[31:28],
P548: if_id_instruction[25:0],
P549: 2'b00
P550: };
P551: jal 指令将返回地址写入 $31：
P552: assign link_address = ex_pc4 + 32'd4;
P553: assign alu_result =
P554: is_jump_link ? link_address : alu_raw_result;
P555: 由于 ex_pc4 等于当前指令地址加 4，所以写入 $31 的实际返回地址为 PC + 8。
P556: jr 指令则从寄存器中读取跳转地址：
P557: assign next_pc =
P558: id_jump
P559: ? (is_jump_register ? id_rs_value : jump_addr)
P560: : (branch_taken ? branch_addr : pc_next4);
P561: 测试程序中的 jal、jr、beq、bne 和 j 用于验证子程序调用、循环执行、条件分支和无条件跳转。

P615: 实验总结
P616: 本实验完成了五级流水线 CPU 的设计与仿真，实现了 IF、ID、EX、MEM 和 WB 五个阶段，并通过流水线寄存器传递数据与控制信号。处理器能够执行算术、逻辑、移位、访存、分支及跳转等测试指令。
P617: 设计中使用数据前递解决大部分数据冒险，并通过 stall 和 bubble 处理 load-use 冒险。仿真结果表明，各级流水线能够正常工作，指令执行结果符合预期。通过本实验，我加深了对流水线数据通路、冒险处理和控制信号传递过程的理解。
